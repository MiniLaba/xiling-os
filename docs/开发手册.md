# 汐灵 OS 开发手册（当前开发模式）

这份手册给继续改这个仓库的同学。它描述 **现在能跑起来的开发模式**，不是安装包里的旧界面。安装包先不要重新打包，等最后一位改完的同学再打。

事实以代码和测试为准。产品结构见 [ADR 0044](adr/0044-pi-native-harness-and-four-entries.md)，总设计见仓库根目录 [DESIGN.md](../DESIGN.md)。

## 现在的产品

工作区侧栏只有四个入口：

| 入口 | 做什么 | 主要代码 |
| --- | --- | --- |
| Chat | 每个项目一条长对话。搜索、提问、看模型回复 | `apps/web/src/chat/ChatView.tsx` |
| Brain | 搜索笔记、聊天片段、论文、图表、报告；笔记、邻域图、文献 | `apps/web/src/brain/BrainView.tsx` |
| Bot | 交办任务，在本机、远程 SSH 或虚拟机上执行；定时任务 | `apps/web/src/bot/BotView.tsx` |
| Settings | 主题、模型、后台运行、项目管理、执行目标、技能、MCP、凭据 | `apps/web/src/settings/SettingsView.tsx` |

Chat 和 Bot 不共用一条记录。Bot 使用标题为 `Bot 交办` 的会话，聊天列表和 Brain 的聊天搜索会跳过它。

## 启动开发模式

环境：Node.js `>=22.19.0`，pnpm `11.19.0`。Windows 上把 `C:\Program Files\nodejs` 放在 PATH 前面。若 `pnpm install` 因 `C:\Program Files\nodejs\node_cache` 报 `EPERM`，先设：

```powershell
$env:npm_config_cache = "$env:TEMP\npm-cache-xiling"
```

在仓库根目录：

```powershell
corepack enable
pnpm install
pnpm dev
```

- 页面：<http://127.0.0.1:4318/>
- API：<http://127.0.0.1:4317/>
- 数据：`%LOCALAPPDATA%\XiLingOS`。项目和对话在 `workspace` 里，定时任务是 `workspace\bot-routines.json`。

`pnpm dev` 会先构建除 server、web、desktop 以外的 workspace 包，再并行 watch。改 `apps/server/src` 后 tsx 会重启 API，重启的几秒内页面可能显示 502，等 API 起来再刷新。改 `packages/*` 后要重新构建对应包，例如：

```powershell
pnpm --filter @xiling/agent-harness build
pnpm --filter @xiling/pi-runtime build
```

Server 和 Web 直接吃源码，不必先 `tsc` 进 `dist` 才能看页面。业务包不要直接 `import` `@earendil-works/pi`，Pi 只留在 `@xiling/pi-runtime`，当前锁的是 0.87.1。

写接口的请求要带本机令牌头 `x-xiling-token`。浏览器里的页面会自己带。手测时先在回环地址 `GET /api/auth/token` 取值。`DELETE` 不要带 `Content-Type: application/json` 的空 body，否则会 400。

## 改界面时去哪

- 四个入口的壳：`apps/web/src/App.tsx`
- 四入口样式最后加载：`apps/web/src/styles/four-entry.css`，颜色令牌在 `apps/web/src/styles/tokens.css`
- Brain 的「打开项目管理」进入 Settings 的项目管理；文献和邻域图仍留在 Brain 里切换
- 文献检索空状态在 `apps/web/src/papers/PaperGraphView.tsx`，Wiki 总览在 `apps/web/src/wiki/WikiView.tsx`

模型在 Settings 里配置。主模型用 DeepSeek 时，模型 ID 必须是模型名（如 `deepseek-v4-pro`），不能把 API Key 存成模型名。

## Bot 怎么执行

执行目标存在工作区设置里，Bot 页和 Settings 的「执行目标」写的是同一份。选项是本机、远程 SSH、虚拟机。SSH 主机形如 `user@host`，并且这台开发机要能免密 `ssh`（`BatchMode`，不会弹出密码框）。

虚拟机是 Docker 镜像 `consol/debian-xfce-vnc`，容器名 `xiling-bot-desktop`，只把 noVNC 发布到 `127.0.0.1`。API 重启会清掉带沙箱标签的容器，画面要在 Bot 里重新打开。嵌入地址必须是 `http://127.0.0.1`。

交办后的真实动作不依赖模型是否调用工具。模型经常只写步骤，Server 会在回合结束时改写回复：

| 用户原话 | 代码 | 结果 |
| --- | --- | --- |
| 现在打开网页、下载论文、列出目录 | `assigned-browse.ts`、`assigned-download.ts`、`assigned-inspect.ts` | 立刻在当前目标上做完 |
| 带钟点的今天、每天、工作日，或写了「每小时」 | `deferred-assignment.ts` | 这一轮不执行，界面询问是否加入定时任务 |
| 用户点「加入」且到点 | `bot-routines.ts` | 用去掉钟点后的指令再跑一轮，那时才会下载或打开 |

定时任务存在本机 `bot-routines.json`。`今天` 是只跑一次的 `once`；`每天` 是 `daily`。钟点以用户原话为准。单篇 PDF 下载上限 40MB。正式 Claim/Evidence 和大范围数据下载仍要审批，不会直接写进科研图。

OpenManus 只是执行边界（`openmanus-boundary.ts`），不是第二个模型循环。

## 改完怎么验

只动了某一块时，跑对应测试即可：

```powershell
pnpm exec vitest run apps/server/src/assigned-download.test.ts apps/server/src/assigned-browse.test.ts apps/server/src/assigned-inspect.test.ts apps/server/src/deferred-assignment.test.ts apps/server/src/bot-routines.test.ts apps/web/src/bot/routine-proposal.test.ts
```

改了包边界或文档链接时：

```powershell
pnpm docs:check
pnpm --filter @xiling/web typecheck
pnpm --filter @xiling/server exec tsc -p tsconfig.json --noEmit
```

全量门禁是 `pnpm check`，比较慢。不要把没跑过的检查写成已经通过。

## 先不要做

- 不要运行 `pnpm desktop:pack` 或 `一键打包.bat`。当前安装包保持原样，最后一位改完的同学再打包。
- 不要把 API Key、`.env`、`%LOCALAPPDATA%\XiLingOS` 里的数据库提交进 Git。
- 不要在 Chat 里再造多条会话、运行图或子智能体委派。那是 ADR 0044 已经退出主路径的做法。
- 不要为了「模型没调用工具」只改提示词。下载、打开网页、列目录、到点再做，都要在 Server 的 settle 路径里兜住。
