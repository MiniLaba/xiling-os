# 最短交付路线：真实 AI OS → 系统级虚拟伴侣

生效：2026-09-05，用户要求压缩步骤、普通步骤无需确认，完成虚拟伴侣后再停止。此文取代 P0–P6 的执行顺序，原记录保留作缺口清单，不削减产品承诺。

## 仅三个连续交付阶段

| 阶段 | 一次性交付范围 | 完成证据 |
| --- | --- | --- |
| A 真实任务闭环 | 内置 Harness、统一模型/自定义端点/凭据、取消、Session 历史、受限工具与产物交付 | 真模型完成小任务并形成可打开产物；无权限拒绝；取消停止；重启不串会话 |
| B 可组合应用 OS | 持久 App 生命周期、用户/Main/App 同一调用入口、按权限传产物、可恢复任务、可信 UI、可审阅记忆与资源回收 | 同一 App 直接和委托都能交付；重启身份/产物保持；跨 App 越权失败；空闲无常驻 Agent 进程 |
| C 系统级虚拟伴侣 | 开源表现层选型/授权、文字交互、真实任务反馈、打开结果、可关闭/少动画；语音只在真实支持时启用 | 从伴侣发起同一 Main 任务、取消和打开产物；不建第二份状态/记忆；关闭释放资源；键盘可用；不默认监听 |

当前（2026-09-06）：A 的真实 SDK、宿主工具、显式文件输入、产物交付、官方压缩机制已实现，公网模型验收尚缺；B 已接入 App 委托、可信追问、记忆审阅和原生导出，完整委托恢复验收尚缺；C 文字伴侣已实现并在原生桌面操作，复用 Main 的任务/会话和状态，不另起 Agent。语音和 VRM 没有实现，不提供假按钮。见 ADR 0053。

本批推进：自定义 HTTP(S) 端点与协议进入内置 Harness 配置，密钥仍通过单独环境变量传递；Main 支持继续已选 Session，提交异步返回并用事件刷新。已通过凭据桥定向测试，未进行真实模型网络调用。当前本机新版 credentials 目录仅有 master.key，没有已保存凭据文件；环境凭据是否可用未据此推断。

## 执行约束

2026-09-06：内置 Harness 的 JSONL 跨进程恢复、宿主工具桥、权限拒绝、显式文件输入/导出、产物派生和官方自动压缩均已通过定向 fixture 验证，恢复历史不再重复注入。Main/App/伴侣共用任务事实源；用户保存回答仍是显式产物提升，不替代 Agent 自动产物。真实提供商端到端、跨重启委托恢复和三平台发布仍待外部验收。见 ADR 0052、0053。

- 合并实现批次；每批只做构建和改动相关的少量定向验证，阶段末做一次端到端。避免每改一处跑全套或反复问“继续吗”。
- App = Persistent Agent；三入口、一个任务事实源、单 Electron 窗口内部多窗口；不恢复旧科研 OS，不引入 Docker/WSL。
- 复用官方循环，OS 工具权限必须在副作用前执行；不开放未经隔离的模型任意代码。
- 原 P4–P6 的产物、记忆、生命周期、替换边界和许可证工作并入 B/C，不能因“少步骤”消失。商店交易/公网发布不在本次授权范围。
- 伴侣按 COMPANION_PLAN.md 的权限与资源边界实施。代码许可证与角色/声音资产授权分别审查，不能从参考产品复制角色。
- 无普通阶段审批；需要新凭据、管理员权限或外部发布授权时仍明确阻塞，不绕过。外部条件未满足时继续其他可推进项，但不得标记全部完成。
- 用户于 2026-09-06 要求停止后续检查；os 自动化已暂停。不得再自行创建续检或以计划任务已运行代替完成证据。
