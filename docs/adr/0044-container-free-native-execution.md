# ADR 0044：Desktop V2 不依赖容器引擎

- 状态：已接受，基础门禁已实现
- 日期：2026-09-02

## 背景

Docker 显著增加桌面应用体积、安装步骤、后台资源占用和 Windows/macOS 故障面。用户决定 Desktop V2 不再依赖 Docker，并卸载开发机上的 Docker Desktop。

## 决策

Desktop V2 的活动 workspace、CI、启动和桌面进程不得安装、探测或调用 Docker。旧版容器实现只存在于冻结标签和维护分支，不作为 V2 运行路径。

V2 首阶段采用受管本机运行时，但只允许运行签名、锁版本、参数受限的内置科研配方。模型生成代码、第三方脚本和未受信任插件默认禁止执行，直到每个平台的系统级沙箱适配器完成并通过安全测试。普通子进程、临时目录和权限提示不得被宣传为沙箱。

## 后果

- 首次安装和启动更简单，Windows 不要求 WSL2 或 Docker Desktop。
- 不再天然获得 Linux 环境一致性，需要锁文件、环境指纹和跨平台黄金任务保证复现。
- 任意代码执行能力延后，不能为了功能演示降低安全边界。
- 远程受控执行可以作为将来 Provider，但不得成为本地应用启动条件。
